# 配置与编辑器

以下路径均相对项目根目录。

## 找到真正加载的数据

| 路径 | 角色 |
|---|---|
| `h5_demo/data/game_cfg.json` | 游戏实际加载的配置真源 |
| `editor/game_cfg_config.json` | 编辑器保存时同步的镜像 |
| `h5_demo/js/game_cfg.js` | 出厂默认配置与合并逻辑 |
| `editor/js/gameDefaults.js` | 编辑器默认模板，派生产物，不直接手改 |
| `editor/project.json`、`h5_demo/data/project.json` | 地图项目与游戏侧项目数据 |
| `h5_demo/data/bgm_config.json`、`h5_demo/data/sfx_config.json` | 游戏侧音频配置，编辑器有对应镜像 |

游戏将真源合并到出厂默认上，数组整体替换。只改出厂数组可能被真源里的旧数组覆盖；不要用整份出厂表覆盖用户真源。更改出厂项时核对真源和镜像；需要生成编辑器默认模板时使用仓库里的 `tools/sync_editor_defaults.js`。

## 编辑器保存与直接改文件

- 顶部分页提供文本、地图编辑、界面立绘、玩法配置、事件和音频等入口；先搜索现有条目再添加，保持稳定编号与变量占位符。
- 地图项目自动保存不代表全部游戏配置已同步。修改后点“保存全部”，等待成功回执，再到游戏验证。
- Agent 直接改配置期间，停止编辑器保存；完成后刷新编辑器，让页面读取新文件。慢请求或旧页面不能覆盖较新的磁盘内容。
- `tools/sync_cfg_jsons.js` 用于补缺，不是所有修改的通用修复工具。删除、改名或换素材后盲目执行，可能把旧条目补回；先核对稳定键、`__removed` 等删除意图和脚本保护范围。
- 保持数组与对象的真实类型；二维数组不能合并成以数字为键的普通对象。

## 素材与文案

素材保留在 `resource/` 对应大类，配置使用项目相对路径。资源按大类管理，目录保持现有结构；故事图片和视频使用 `resource/story/`。

换素材只修改现行配置引用：更新游戏真源与编辑器镜像，删除不用的旧引用。不为单张素材添加运行时改写配置的代码。复用现有图片处理与只读预览组件；分发前核对根目录的 `LICENSE-ASSETS.txt`、`NOTICE.txt`。

台词中的变量先检查当前渲染链路支持的占位符。保持用户完整生成提示词原文，不自行拆分、补充或设本地字符上限。语音候选与正式资源分开；删除候选不能删除游戏正在使用的正式资源。

## 改了没生效时

按证据定位，不按固定清单盲目改文件：

- 浏览器是否打开项目专用服务、实际入口是否是 `h5_demo/index.html`？
- 游戏加载的是哪个 JSON？真源、镜像、出厂默认是否存在同一条目的冲突？
- 是否遗漏“保存全部”、需要重启的后台服务或缓存版本？
- 当前存档是否已经经过该剧情、奖励或解锁节点？新局与读档的触发条件是否不同？
- 条目是否被改名、删除，或由旧编辑器页面补回？

涉及游戏配置时运行当前仓库中的 `node h5_demo/audit_cfg_sync.js`，再按改动范围选测试。只改出厂默认的无头测试不足以验证实际 JSON 配置。
