# 鲸鱼娘项目开发

这是随源码分发的公开版开发 skill，适用于当前项目目录，不依赖作者电脑上的技能、私人路径或内部设计文档。技术说明遵循项目根目录的 MIT 许可；游戏素材仍按对应素材许可使用。

## 接到需求后

先读项目根目录实际存在的 `AGENTS.md` 与 `入门与编辑器指南.md`，再根据用户描述定位实现。用户可以用自然语言提出需求，不必预先知道文件名。保留用户已调整的内容，以本次需求确定修改范围；不把内部历史实现当作必须恢复的目标。

1. 用界面原文、配置键或函数名检索 `h5_demo/`、`editor/` 和必要的 `tools/`。实际游戏入口是 `h5_demo/index.html`；根目录旧 HTML 不代表运行版本。
2. 确认游戏实际加载源、编辑器写入目标和现有组件，再修改。资源、文案和数值保存在配置里；换素材只换引用源，不新增迁移、兼容或兜底钩子。
3. 沿现有 UI、动效和操作流程实现需求。用户明确要求改变交互时再改变交互，不为局部调整重新设计整套界面。
4. 按修改范围运行专项检查，并实际触发对应页面或流程。说明改了哪些文件、怎样验证，以及尚未覆盖的条件。

## 常见决策

- 想换背景、人物图片或一句文案：先找配置和编辑器入口，避免直接改渲染函数或写死素材路径。
- 编辑器不能覆盖某项需求：找到现有组件或引擎接口扩展，并维持配置驱动；有必要时让编辑器也能编辑新字段。
- 用户说“改了没用”：核对入口、加载顺序、真源与镜像、浏览器缓存、触发条件及存档进度；不要先叠加另一层修补代码。
- 用户说“保存失败”：保留页面输入与磁盘原文件，核对服务回执和冲突，不用旧页面强行覆盖。
- 本地改动验收不等于线上发布。根据当前仓库的实际分支和用户要求开展协作，不依赖作者私有发布脚本。
